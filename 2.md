## 1. Introduction

### 1.1 Purpose
This document provides complete technical and operational instructions for the **BetterGrowth Mail System** — a web-based transactional email platform built on serverless infrastructure.

### 1.2 Scope
The system supports:
- Secure user authentication
- Sending emails from a custom domain
- File attachments (with automatic image compression)
- Sent email history with detailed preview
- Resend and delete operations

### 1.3 Intended Audience

| Audience | Use |
|----------|-----|
| Developers | Setup, deployment, debugging |
| System Admins | Maintenance, monitoring |
| End Users | Daily sending, viewing history |

### 1.4 Definitions

| Term | Meaning |
|------|---------|
| Edge Function | Serverless function running at Supabase |
| RLS | Row Level Security (Postgres) |
| JWT | JSON Web Token (auth session) |
| SMTP | Email sending protocol |
| DKIM/SPF | Email authentication standards |

### 7.4 SQL — Tables

Execute in SQL Editor:

```sql
drop table if exists sent_emails cascade;

create table sent_emails (
  id               uuid primary key default gen_random_uuid(),
  to_email         text,
  cc_email         text,
  bcc_email        text,
  subject          text,
  body             text,
  attachment_name  text,
  attachment_url   text,
  attachment_path  text,
  resend_id        text,
  status           text,
  sent_by          uuid references auth.users(id),
  created_at       timestamptz default now()
);

alter table sent_emails enable row level security;

create policy "users read own sends"
  on sent_emails for select
  to authenticated
  using (auth.uid() = sent_by);

create policy "users insert own sends"
  on sent_emails for insert
  to authenticated
  with check (auth.uid() = sent_by);

create policy "users delete own sends"
  on sent_emails for delete
  to authenticated
  using (auth.uid() = sent_by);
```

### 7.5 SQL — Storage Policies

```sql
drop policy if exists "auth upload attachments" on storage.objects;
drop policy if exists "auth read attachments"   on storage.objects;
drop policy if exists "auth delete attachments" on storage.objects;

create policy "auth upload attachments"
  on storage.objects for insert
  to authenticated
  with check (bucket_id = 'attachments');

create policy "auth read attachments"
  on storage.objects for select
  to public
  using (bucket_id = 'attachments');

create policy "auth delete attachments"
  on storage.objects for delete
  to authenticated
  using (bucket_id = 'attachments');
```

### 10.4 Optional Router (`_worker.js`)

```js
export default {
  async fetch(request, env) {
    const url = new URL(request.url);
    let path = url.pathname;
    if (path === "/" || path === "") path = "/index.html";

    if (!path.includes(".")) {
      const res = await env.ASSETS.fetch(
        new Request(new URL(path + ".html", url), request)
      );
      if (res.status !== 404) return res;
    }
    return env.ASSETS.fetch(request);
  },
};
```

## 11. API Specification

**Base URL**
```
https://<REF>.supabase.co/functions/v1/send-email
```

**Authentication**
All endpoints (except `login`) require:

```
Authorization: Bearer <access_token>
```

### 11.1 Endpoint Summary

| Method | Action | Purpose |
|--------|--------|---------|
| POST | `?action=login` | Authenticate |
| POST | `?action=send` | Send email |
| GET | `?action=sent` | List emails |
| GET | `?action=get&id=<uuid>` | Fetch one |
| GET | `?action=last` | Latest email |
| POST | `?action=delete` | Delete email |

### 11.2 Detailed Endpoints

#### 11.2.1 Login

**Request**
```json
{ "email": "user@example.com", "password": "•••" }
```

**Response 200**
```json
{
  "ok": true,
  "access_token": "eyJ...",
  "user": { "id": "uuid", "email": "user@example.com" }
}
```

**Response 401**
```json
{ "error": "Invalid login credentials" }
```

#### 11.2.2 Send

**Request**
```json
{
  "to": "a@x.com, b@x.com",
  "cc": "c@x.com",
  "bcc": "d@x.com",
  "subject": "Interview Invitation",
  "html": "<p>Hello…</p>",
  "attachment": {
    "filename": "resume.pdf",
    "content": "<base64>",
    "contentType": "application/pdf"
  }
}
```

**Response 200**
```json
{
  "ok": true,
  "resend": { "id": "01a0fc72-..." },
  "attachment_url": "https://..."
}
```

#### 11.2.3 Sent List

**Response 200** — Array of email objects.

#### 11.2.4 Get One

| Param | Type | Required |
|-------|------|----------|
| id | uuid | Yes |

**Response 200** — Email object.
**Response 404** — `{ "error": "Not found" }`

#### 11.2.5 Last Email

**Response 200** — Email object or `null`.

#### 11.2.6 Delete

**Request**
```json
{ "id": "uuid" }
```

**Response 200**
```json
{ "ok": true }
```

### 11.3 Status Codes

| Code | Description |
|------|-------------|
| 200 | Success |
| 400 | Bad Request |
| 401 | Unauthorized |
| 404 | Not Found |
| 500 | Server Error |

## 14. Security

### 14.1 Secret Management

| Secret | Location | Visibility |
|--------|----------|------------|
| Resend API Key | Supabase Secrets | Server only |
| Service Role Key | Auto-injected | Server only |
| Anon Key | Public HTML | Safe |
| Passwords | Supabase Auth | Hashed |
| JWT | Browser localStorage | Session |

### 14.2 Security Rules

1. Never commit keys to GitHub
2. Never expose service_role in browser
3. Rotate keys if leaked
4. Keep DNS records in **DNS-only** mode
5. Enable RLS on all tables
6. Use HTTPS only

### 14.3 Incident Response

| Event | Action |
|-------|--------|
| Key leaked | Rotate immediately |
| Password leaked | Reset in Supabase Auth |
| Suspicious login | Audit Auth logs |
| Storage misuse | Review bucket policies |

## 16. Troubleshooting

### 16.1 Error Reference

| Error | Cause | Fix |
|-------|-------|-----|
| `Invalid login credentials` | Wrong password / unconfirmed | Reset in Auth UI |
| `Unauthorized` | Expired token | Re-login |
| `Missing email ID` | URL lacks `?id=` | Fix link |
| `Not found` | Ownership mismatch | Verify sent_by |
| `Unknown action` | Function not deployed | Redeploy |
| Invalid UUID error | Placeholder not replaced | Use real UUID |
| Image not previewing | `attachment_url` null | Check Storage logs |

### 16.2 Diagnostic Queries

**Recent Sends**
```sql
select id, to_email, subject, status, attachment_url, created_at
from sent_emails
order by created_at desc
limit 20;
```

**Ownership Check**
```sql
select u.email, count(s.id) as sent
from auth.users u
left join sent_emails s on s.sent_by = u.id
group by u.email;
```

**Fix Orphans**
```sql
update sent_emails
set sent_by = (select id from auth.users
               where email = 'hr@bettergrowthsolutions.com')
where sent_by is null;
```
