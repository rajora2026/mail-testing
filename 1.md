## 1. Overview

### 1.1 Purpose

The **BetterGrowth Mail System** is a lightweight, zero-cost web application for sending transactional emails (interview invites, HR communication) from a custom domain with:

- Secure login
- Attachments (images auto-compressed)
- CC / BCC support
- Full sent history
- Detailed preview page with image/PDF viewer
- Resend & Delete actions

### 1.2 Scope

| In Scope | Out of Scope |
|---|---|
| Outbound email sending | Inbound email receiving |
| Attachments up to 10 MB | Email threading / replies |
| Sent history with preview | Bulk email campaigns |
| Single HR user (extensible) | Marketing automation |

### 1.3 Key Benefits

- **₹0 cost** — all free tiers
- **No exposed secrets** — all keys server-side
- **Custom domain** — sends from `hr@bettergrowthsolutions.com`
- **Auto image compression** — ~85% size reduction
- **Full audit trail** — every send logged

## 2. System Architecture

### 2.1 High-Level Diagram

```
┌──────────────────────────────────────────┐
│         Browser (Cloudflare Worker)      │
│  index.html · send.html · sent.html      │
│              view.html                    │
└──────────────────┬───────────────────────┘
                   │ HTTPS
                   ▼
┌──────────────────────────────────────────┐
│      Supabase Edge Function (Deno)       │
│         send-email  (router)             │
│  ┌────────────────────────────────────┐  │
│  │ login · send · sent · get ·        │  │
│  │ last · delete                      │  │
│  └────────────────────────────────────┘  │
└──┬────────────┬─────────────┬────────────┘
   │            │             │
   ▼            ▼             ▼
┌──────┐   ┌────────┐   ┌──────────┐
│ Auth │   │  DB    │   │ Storage  │
│(JWT) │   │(sends) │   │(files)   │
└──────┘   └────────┘   └──────────┘
                   │
                   ▼
            ┌────────────┐
            │  Resend    │
            │  (SMTP)    │
            └────────────┘
```

### 2.2 Request Flow (Send Email)

```
1. User fills form on /send
2. Browser compresses image (if any) → WebP
3. POST /functions/v1/send-email?action=send
   ├─ Header: Authorization: Bearer <jwt>
   └─ Body: { to, cc, bcc, subject, html, attachment }
4. Edge Function:
   a. Verifies JWT via Supabase Auth
   b. Uploads attachment to Storage → gets public URL
   c. Calls Resend API
   d. Inserts row into sent_emails
5. Returns { ok, resend, attachment_url }
6. Browser shows success + resets form
```

### 6.4 Run SQL — Table

In **SQL Editor**, execute:

```sql
drop table if exists sent_emails cascade;

create table sent_emails (
  id               uuid primary key default gen_random_uuid(),
  to_email         text,
  cc_email         text,
  bcc_email        text,
  subject          text,
  body             text,
  attachment_name  text,
  attachment_url   text,
  attachment_path  text,
  resend_id        text,
  status           text,
  sent_by          uuid references auth.users(id),
  created_at       timestamptz default now()
);

alter table sent_emails enable row level security;

create policy "users read own sends"
  on sent_emails for select
  to authenticated
  using (auth.uid() = sent_by);

create policy "users insert own sends"
  on sent_emails for insert
  to authenticated
  with check (auth.uid() = sent_by);

create policy "users delete own sends"
  on sent_emails for delete
  to authenticated
  using (auth.uid() = sent_by);
```

### 6.5 Run SQL — Storage Policies

```sql
drop policy if exists "auth upload attachments" on storage.objects;
drop policy if exists "auth read attachments"   on storage.objects;
drop policy if exists "auth delete attachments" on storage.objects;

create policy "auth upload attachments"
  on storage.objects for insert
  to authenticated
  with check (bucket_id = 'attachments');

create policy "auth read attachments"
  on storage.objects for select
  to public
  using (bucket_id = 'attachments');

create policy "auth delete attachments"
  on storage.objects for delete
  to authenticated
  using (bucket_id = 'attachments');
```

### 9.4 Optional — Worker Routing

If `/view` returns 404, add `_worker.js`:

```js
export default {
  async fetch(request, env) {
    const url = new URL(request.url);
    let path = url.pathname;

    if (path === "/" || path === "") path = "/index.html";

    if (!path.includes(".")) {
      const res = await env.ASSETS.fetch(
        new Request(new URL(path + ".html", url), request)
      );
      if (res.status !== 404) return res;
    }
    return env.ASSETS.fetch(request);
  },
};
```

## 10. API Reference

**Base URL:**
```
https://<PROJECT_REF>.supabase.co/functions/v1/send-email
```

### 10.1 Authentication

All endpoints except `login` require:

```
Authorization: Bearer <access_token>
```

### 10.2 Endpoints

#### `POST ?action=login`

Authenticate user.

**Request:**
```json
{ "email": "hr@...", "password": "..." }
```

**Response 200:**
```json
{
  "ok": true,
  "access_token": "eyJ...",
  "user": { "id": "uuid", "email": "hr@..." }
}
```

**Response 401:**
```json
{ "error": "Invalid login credentials" }
```

---

#### `POST ?action=send`

Send an email.

**Request:**
```json
{
  "to": "a@x.com, b@x.com",
  "cc": "c@x.com",
  "bcc": "d@x.com",
  "subject": "Interview",
  "html": "<p>Hi</p>",
  "attachment": {
    "filename": "resume.pdf",
    "content": "base64...",
    "contentType": "application/pdf"
  }
}
```

**Response 200:**
```json
{
  "ok": true,
  "resend": { "id": "01a0fc72-..." },
  "attachment_url": "https://.../attachments/..."
}
```

---

#### `GET ?action=sent`

List sends (most recent first, max 200).

**Response 200:** Array of email objects.

---

#### `GET ?action=get&id=<uuid>`

Get one email by ID.

**Response 200:** Email object.
**Response 404:** `{ "error": "Not found" }`

---

#### `GET ?action=last`

Get most recent send.

**Response 200:** Email object or `null`.

---

#### `POST ?action=delete`

Delete email + attachment.

**Request:**
```json
{ "id": "uuid" }
```

**Response 200:** `{ "ok": true }`

---

### 10.3 Status Codes

| Code | Meaning |
|---|---|
| 200 | Success |
| 400 | Bad request / missing fields |
| 401 | Unauthorized / bad credentials |
| 404 | Not found / unknown action |
| 500 | Server error |

## 13. Security

### 13.1 Secret Management

| Secret | Location | Exposure |
|---|---|---|
| Resend API key | Supabase Edge Function Secrets | Server only |
| Service role key | Auto-injected by Supabase | Server only |
| Anon key | Public HTML | Safe |
| User passwords | Supabase Auth (hashed) | Never visible |
| JWT | Browser localStorage | Session only |

### 13.2 Security Rules

1. ❌ Never commit keys to GitHub
2. ❌ Never hardcode keys in HTML
3. ✅ Rotate Resend key if it leaks
4. ✅ Use DNS-only for MX/SPF/DKIM in Cloudflare
5. ✅ RLS enabled on all tables

### 13.3 Password Rotation

If a password leaks:
1. Supabase → Auth → Users → Reset Password
2. Resend → API Keys → Delete → Create new
3. Update Edge Function secret
4. Redeploy

## 14. Troubleshooting

### 14.1 Common Errors

| Error | Cause | Solution |
|---|---|---|
| `Invalid login credentials` | Wrong password or unconfirmed user | Reset via Auth UI |
| `Unauthorized` | Token expired | Log out, log in |
| `Missing email ID` | URL missing `?id=` | Fix link to `view?id=...` |
| `Not found` | `sent_by` mismatch | Check user ID |
| `Unknown action` | Function not deployed | Redeploy Edge Function |
| `invalid input syntax for type uuid` | Placeholder not replaced | Use real UUID |
| Image not previewing | `attachment_url` null | Check Storage logs |

### 14.2 Diagnostic Queries

**Recent sends:**
```sql
select id, to_email, subject, status, attachment_url, created_at
from sent_emails
order by created_at desc
limit 20;
```

**Check ownership:**
```sql
select u.email, count(s.id)
from auth.users u
left join sent_emails s on s.sent_by = u.id
group by u.email;
```

**Fix orphaned rows:**
```sql
update sent_emails
set sent_by = (select id from auth.users where email = 'hr@bettergrowthsolutions.com')
where sent_by is null;
```
